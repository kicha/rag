What does ef_construct control?

HYPOTHETICAL DOCUMENT
--------------------------------------------------------------------------------
`ef_construct` (often written as `efConstruction`) is a parameter of the HNSW (Hierarchical Navigable Small World) graph algorithm that determines the size of the dynamic candidate list used during index construction. A larger `ef_construct` value increases the number of nearest‑neighbor candidates examined when inserting a newelement, which typically improves recall and graph connectivity at the cost of higher construction time and memory usage. Conversely, a smaller value speeds up index building but may reduce search accuracy.

How does the M parameter affect HNSW?

HYPOTHETICAL DOCUMENT
--------------------------------------------------------------------------------
In Hierarchical Navigable Small World (HNSW) graphs, the **M** parameter determines the maximum number of bi‑directional links that each node may maintain in the upper layers of the structure. Larger values of M increase the graph’s connectivity, which typically improves recall and search robustness at the cost of higher memoryconsumption and longer index construction time. Conversely, smaller M values reduce memory usage and index build time but may degrade search accuracy and increase the number of distance computations required during query traversal.

What metadata can be stored with vectors?

HYPOTHETICAL DOCUMENT
--------------------------------------------------------------------------------
Vector stores typically associate each embedding with a set of metadata fields that are persisted alongside the numeric vector. Common metadata includes a unique identifier, timestamps for creation or update, source document references (such as URLs or file paths), categorical tags, and any custom key‑value attributes required for downstream filtering or ranking. These fields are indexed separately from the vector index, enabling efficient metadata‑based queries without affecting similarity search performance.
